# Pipeline Architecture Spec — Mind the Box Platform

**What this document is:** The single source of truth for how the entire system works. Every rule, every boundary, every ownership decision. If it's not in here, it hasn't been decided.

**Status key:** ✅ Built | 🔧 In progress | 📋 Specced | 🔮 Planned

## Part 1 — Ownership: Who Controls What

| Layer | Who owns it | What it decides | Can AI change it? |
|---|---|---|---|
| **Atom CSS** | You, audited once | How components render in every mode | No — locked after audit |
| **Schemas** | You, audited once | What props are valid, what enums exist | No — locked after audit |
| **Global CSS tokens** | Theme files + token files | Colours, spacing, shadows, radius, typography | No — generated by theme engine |
| **Global gate CSS** | Gate files | Hover speed, motion speed, glass/solid, single column | No — user toggles via Your View |
| **Global rules CSS** | Global files | Transitions, highlight-links, focus rings | No — locked after audit |
| **Brand config** | One JSON file per brand | Default overrides (shape, variant) per component | AI generates once, you approve |
| **Content** | AI generates, Worker validates | Words, structure, purpose flags | AI writes content only — no design values |
| **Page JSON** | Worker assembles | Complete page data with all props | Worker fills from schemas + brand config |
| **Astro pages** | Dumb renderer | Reads JSON, maps to components, outputs HTML | Never makes decisions |

### The iron rule:
CSS is locked. Schemas are locked. Workers filter. AI writes words. Nobody goes rogue because the constraints are in code, not instructions.

## Part 2 — Token Layers

### Never-change foundation tokens
Live in `src/styles/tokens/`. Spacing, typography, radius, shadows, z-index, borders. Same across all brands, all themes.

**Status:** ✅ Built

### Colour scale tokens
Live in theme files (`src/styles/themes/`). Primary 100–950, secondary 100–950, neutral 100–950. Generated by theme engine from two hex codes. Dark mode flips the scale so every position is contextually correct.

**Status:** ✅ Built (112 theme files). 🔧 Scale flip for dark mode specced, not implemented yet. 📋 Neutral-300 position needs adding.

### Page surface tokens
`--page-bg`, `--page-bg-raised`, `--page-bg-sunken`, `--page-bg-overlay`. Set per theme. Dark mode uses M2 spec (#121212 base).

**Status:** ✅ Built

### Glass tokens
`--glass-bg`, `--glass-border`, `--glass-blur` and variants. Live in global CSS. Swappable via visual mode file — default (transparent) or solid (opaque).

**Status:** ✅ Glass tokens built. 📋 Solid swap file planned, not built.

### Shadow tokens
`--shadow-sm` through `--shadow-elevated`, `--glow-neon`, `--glow-ambient` etc. Live in `shadows.css`. Dark mode zone file kills shadows, enables glow system.

**Status:** ✅ Built

### Rainbow tokens
7 colours × 5 tints = 35 tokens. Four CVD palettes: default ROYGBIV, protan-safe, tritan-safe, monochrome. Global CSS files, not per-theme. Dark mode flips wash↔deep, light↔dark.

**Status:** ✅ Built

### Text tokens
`--text-body`, `--text-secondary`, `--text-emphasis`, `--text-inverse`. WCAG-validated per luminance mode. Set per theme.

**Status:** ✅ Built

### Component bridge tokens
`var(--heading-color)`, `var(--badge-bg)` etc. Pipeline provides values via inline style. No fallbacks in CSS — missing values break visibly.

**Status:** 🔧 Fallbacks being stripped during audit. Pipeline not providing values yet.

## Part 4 — Render Modes

Three modes. Not four. ~~Assistive~~ is a preset, not a render mode.

| Mode | Data attribute | What changes | Who decides |
|---|---|---|---|
| **Full** | `data-render="full"` | Everything loaded | Default |
| **Reduced** | `data-render="reduced"` | Animation props not in JSON. No motion classes emitted. CSS motion tokens = 0. | User via Your View |
| **Textonly** | `data-render="textonly"` | Content props only. No images (unless `purpose="informational"`). No visual variants. Single column. Accordion fallback for long content. | User via Your View |

### How render modes work:
1. **Pipeline generates different JSON per mode** — schema flags (`"textonly": false`) control which props are included
2. **CSS gates adjust containers** — padding, columns, borders for content that IS rendered
3. **Components are pure** — always render what they receive, never check mode
4. **JS animation gate** — `shouldAnimate()` checks `data-render`, returns false for reduced/textonly

### The purpose flag:
Every image and animation in JSON declares purpose:

| Purpose | Full | Reduced | Textonly |
|---|---|---|---|
| `decorative` | Show | Show | Not loaded |
| `informational` | Show | Show (static fallback) | Show |

**Status:** ✅ Render modes built. 🔧 Assistive rules being removed from components. 📋 Purpose flag on JSON planned.

## Part 5 — Visual Modes (Token File Swaps)

Visual modes change HOW things look. Render modes change WHAT exists. Independent axes.

| Mode | Mechanism | File |
|---|---|---|
| Luminance (light/dark) | Different theme file loaded | Theme files |
| Chroma (brand/neon/pastel/grey) | Theme meta, zone file | `theme-chroma-mono.css` |
| Intensity (full/soft) | Zone file | `theme-intensity-soft.css` |
| Glass (default/solid) | Visual mode file swap | `visual/default/` or `visual/solid/` |

### Assistive preset
Not a render mode. A preset in Your View that sets multiple data attributes at once:
- `data-hover="none"`
- `data-highlight-links`
- `data-glass="solid"`
- `data-assistive` (sets `--min-target: 64px`, `--focus-ring-width: 3px`, `--border-width: 2px`)

User can toggle any individual setting back off after applying the preset.

**Status:** ✅ Zone files built. 📋 Glass swap planned. 📋 Assistive preset planned.

## Part 6 — Gates (Data Attributes on Body)

Every gate is a data attribute on `<body>`. Your View panel toggles them. They compose freely.

| Attribute | Values | What it controls |
|---|---|---|
| `data-render` | full / reduced / textonly | What content exists |
| `data-hover` | full / gentle / instant / none | Hover transition speed |
| `data-motion` | full / gentle / minimal / none | Animation speed, scroll behaviour |
| `data-highlight-links` | present / absent | Visible border on all clickable |
| `data-glass` | default / solid | Glass transparency or opaque |
| `data-high-contrast` | present / absent | Maximum contrast overrides |
| `data-layout` | default / single / presentation | Column layout |
| `data-assistive` | present / absent | Enlarged targets, thick borders |
| `data-alt-text-mode` | word / descriptive / aac | Which alt text layer to show |
| `data-alt-display-mode` | hidden / caption / overlay / tooltip / enlarge / replace | How alt text is displayed |
| `data-core-tier` | green / yellow / orange / full | AAC vocabulary filtering |

**Status:** ✅ hover, render, highlight-links, high-contrast, alt modes, core-tier built. 📋 motion, glass, layout, assistive planned.

## Part 7 — Responsive

### Global approach:
One html font-size per breakpoint. Everything in `rem` scales proportionally. `em` for icons inside text.

```
Desktop (1024+): 100% (16px)
Tablet (768):    93.75% (15px)
Mobile (480):    87.5% (14px)
Small (300):     80% (~13px)
Micro (200):     75% (12px)
```

### Global token overrides per breakpoint:
Typography, spacing, section padding — all handled globally. Component responsive files only for layout edge cases (flex-direction, element hiding, grid collapse).

### Wide screens:
```
Large (1920+):   112.5% font, 4 grid columns
Ultra (2560+):   125% font, 5 grid columns
Presentation:    150% font, single column, max-width constrained
```

### Single column:
One token `--grid-columns: 1`, three triggers:
- `@media (max-width: 480px)` — mobile
- `[data-render="textonly"]` — text mode
- `[data-layout="single"]` — user preference

**Status:** ✅ Global responsive files exist. 🔧 Per-component duplicates need stripping. 📋 Font-size scaling approach specced.

## Part 8 — Component Architecture

### Atoms (15)
Pure building blocks. Read tokens. No mode checks. No parent awareness.

**Primary (10):** Text, Heading, Button, Badge, Link, Icon, Image, Card, List, FormField
**Supporting (5):** Toast, Tooltip, Grid, ScrollDrawIcon, LottieIcon

Rules:
- External CSS only. No scoped `<style>`.
- Read tokens, never define colour values.
- Compose other atoms (Heading uses Icon, Text, LottieIcon). Never import molecules.
- Schema defines everything: props, groups, defaults, enums.
- Icons inside text use `em`. Standalone icons use `rem`.

### Molecules (~25+)
Compose atoms into specific layouts. JSON describes them, they render atoms inside.

Examples: BlogCard, AuthorCard, CompactToolCard, FlipCard, CardReveal, RainbowBorderCard

Rules:
- Pass JSON props through to atoms.
- Own layout CSS between atoms.
- Own their colour tokens for molecule-level concerns (face backgrounds, hover accents).
- `renders` block routes to different components per mode (FlipCard → CardReveal in textonly).

### Effects
Visual wrappers. Animation gated by props. Purely decorative.

Examples: RainbowBorder, GlowSection, TextEffect, PatternOverlay, ParallaxDecor

Rules:
- `aria-hidden="true"` on decorative effects.
- JS animation checks global gate before running.
- Static fallback for informational effects in reduced mode.

### Organisms
Compose molecules/atoms into page sections. Own section-level layout.

Examples: HeroSection, Grid, GlassNav, Footer, ContactForm

### Section container
Every section wrapped in `<Section>`. Owns horizontal padding (`--page-margin`) and vertical rhythm (`--space-section`). Global tokens control all of it.

**Status:** ✅ Atoms mostly audited. 🔧 Molecules in progress. 📋 Effects audit deferred. 📋 Organisms not started.

## Part 9 — Schema Rules

### Four prop groups:

| Group | Survives full | Survives reduced | Survives textonly |
|---|---|---|---|
| **content** | ✅ | ✅ | ✅ |
| **visual** | ✅ | ✅ | ❌ |
| **animation** | ✅ | ❌ | ❌ |
| **colour** | ✅ | ✅ | ❌ |

### Schema rules:
- Defaults are token NAMES not CSS VALUES. `"default": "neutral-800"` not `"default": "#565043"`.
- No fallbacks in CSS. Pipeline provides all values.
- `"textonly": false` on decorative props (icons, images, animations).
- `renders` block for pipeline routing when component can't work in a mode.
- Colour tokens map to CSS custom properties via `cssProperty` field.
- Enums are the ONLY valid values. Worker rejects anything not in an enum.

**Status:** ✅ Schema structure established. 🔧 Being cleaned during audit.

## Part 10 — AAC Architecture

### BCI index
6,428 concepts, 18 languages. Canonical in D1. Universal key — every symbol set maps to BCI IDs.

### Dual system:
1. **Content AAC** — inline pictograms alongside headings/text. Built at build time via `aacInline()`. Rendered as `<span class="content-aac" set:html={aacHtml}>`.
2. **Image alt text AAC** — pictogram cards as an alt text display mode. User selects "AAC" from alt text mode in Your View.

### Symbol sets:
- OpenAAC (CC BY-SA 4.0) ✅ Bundled
- Bliss SVGs (CC BY-SA 3.0) ✅ Bundled
- ARASAAC (CC BY-NC-SA) 📋 Planned
- Custom generated (LoRA or Canva) 🔮 Planned

### Cognitive level filtering:
CSS gate via `data-core-tier`. Green = 60 survival words, yellow = 148, orange = 251, full = everything. Pure CSS, no pipeline involvement.

### AAC boards:
Canva Connect API + Apps SDK for user-created boards. Worker generates companion boards from content automatically (concepts already resolved at build time).

**Status:** ✅ BCI index built. ✅ Content AAC working. ✅ Cognitive filtering working. 📋 Canva integration specced. 🔮 Custom symbol generation planned.

## Part 11 — Image Pipeline

### Semantic roles:

| Role | Full | Reduced | Textonly |
|---|---|---|---|
| `decorative` | Show | Show | Not loaded |
| `informational` | Show | Show | Show |
| `interactive` | Show | Show | Show with alt |

### Alt text — three layers:
- **Word** — single short word ("Wardrobe")
- **Descriptive** — full sentence ("A winding path through an autumn forest")
- **AAC HTML** — pre-built pictogram cards

Resolved at build time. Image atom receives finished `altWord`, `altDescriptive`, `altAacHtml`.

### Display modes (user toggles in Your View):
hidden, caption, overlay, tooltip, enlarge, replace

### FigCaption atom:
Sits inside `<figure>`, reads alt text from existing spans. Hover gates control: full/gentle/instant = floating, none = inline.

### Image enlarge modal:
Opens on click when `data-alt-display-mode="enlarge"`. Large image + subtitle alt text + AAC cards. Focus trap, escape to close.

### Image effects (visual group):
`blur` (reveal on hover/click), `maskIcon` (Phosphor SVG as clip mask), `maskShape` (file-based masks), `bgFill` (glass or solid for transparent PNGs).

**Status:** ✅ Image atom audited. ✅ Alt text system built. ✅ Enlarge modal built. ✅ FigCaption built. ✅ Blur reveal built. ✅ Mask system built.

## Part 12 — Animation System

### CSS animations:
Prop → class → CSS. No prop = no class = no match = zero motion.

### JS animations:
Global gate function. Every animation script calls it first:
```
shouldAnimate() → checks data-render
getSpeed() → reads --motion-speed token
```

### Gate files:
- `hover-gate.css` — hover transition speed ✅ Built
- `motion-gate.css` — GSAP/Lottie/SMIL speed multiplier 📋 Specced

### Per-component fallbacks:
Global gate says "don't animate." Component owns what to show instead:
- LottieIcon → fallback icon
- ScrollDrawIcon → completed SVG
- RainbowBorder → solid accent border
- PatternOverlay → freeze SMIL, static grid

### Motion tiers:
full → gentle → minimal → none. One `data-motion` attribute. Your View slider.

### Rules:
- Components never import `gsap` directly. Use the gate wrapper.
- Components never check `data-render` directly. Use `shouldAnimate()`.
- Informational animations MUST have a static fallback. Worker rejects if missing.
- Decorative animations just don't run — nothing to show.
- SMIL frozen via `svg.pauseAnimations()` in reduced.

**Status:** ✅ Hover gate built. 📋 Motion gate specced. 📋 GSAP gate wrapper specced.

## Part 13 — Pipeline Flow

### The chain:
1. **Two hex codes + brand prompt** → AI generates brand config ✅ Theme engine built, 📋 brand config generation planned
2. **Theme engine** → generates theme files with flipped scales, validated contrast ✅ Built (🔧 scale flip pending)
3. **Brand config** → small file, just default overrides per component 📋 Specced
4. **Content AI** → writes words only, no design values 📋 Specced
5. **Worker/script assembles page JSON** → reads schemas + brand config + content → outputs complete JSON 📋 Specced
6. **Validation** → token check, enum check, contrast check, rejects invalid 📋 Specced
7. **Astro renders** → reads JSON, maps to components, outputs HTML ✅ Built
8. **CSS gates** → runtime mode switching, no reload needed ✅ Partially built
9. **Pre-commit hook** → blocks hardcoded values in JSON 📋 Specced
10. **Automated tests** → token, schema, contrast, visual regression, axe scan 📋 Specced

### Content vs website:
- **Website pages** — more design freedom, brand config defaults + overrides in JSON
- **Content (workbooks, exercises, guides)** — consistent structure, brand config defaults only, theme colours change per brand

Same pipeline, same atoms, same schemas. The difference is how much the JSON overrides defaults.

### Brand config:
```json
{
  "brand": "mind-the-box",
  "theme": "default",
  "logo": "/brands/mtb/logo.svg",
  "overrides": {
    "Button": { "shape": "pill" },
    "Badge": { "shape": "pill" },
    "Heading": { "variant": "underline" }
  }
}
```

Tiny. Only what differs from schema defaults. Everything else just works.

**Status:** 📋 Full pipeline specced. Individual pieces at varying stages.

## Part 14 — Banned Patterns

### In CSS:
- No scoped `<style>` blocks in `.astro` files
- No `!important` declarations
- No `@media (prefers-reduced-motion)` in component CSS
- No `.a11y-*` class selectors
- No `#a11y-content-wrapper` references
- No `:global()` selectors
- No `@layer` wrappers
- No `var(--token, fallback)` — no fallback values on tokens
- No `var(--token, #hex)` — no hardcoded hex fallbacks
- No raw `--brand-c-*` references (being deleted)
- No `--zone-bg-*` or `--zone-pattern-*` references
- No hardcoded `px` for font-size (use tokens)
- No hardcoded colours (use scale positions)
- No per-component transition declarations (global handles it)
- No per-component highlight-links rules (global handles it)
- No per-component focus-visible rules (global handles it)
- No `[data-render="assistive"]` rules (preset handles it via global tokens)

### In JS:
- No importing `gsap` directly — use gate wrapper
- No checking `data-render` directly — use `shouldAnimate()`
- No checking legacy `.a11y-reduce-motion` or `.a11y-text-only` classes
- No `isA11yActive()` functions
- No `fs.readFileSync` for loading SVGs — use Icon atom

### In JSON:
- No hex colours (`#ff0000`)
- No rgb/rgba/hsl values
- No raw px values for shadows or sizes
- No CSS values — only token names
- No inline `box-shadow` values
- Schema defaults are token NAMES not CSS VALUES

### In schemas:
- No `"default": "#hex"` — use `"default": "primary-600"`
- No `"default": "0 8px 32px rgba()"` — use `"default": "shadow-lg"`
- Defaults must match what CSS expects
- Every colour prop must map to a `cssProperty`
